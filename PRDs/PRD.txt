PRD - LSQ API & Payload Enhancement - Additional Attribution Parameters
1. Objective
Enhance the existing LeadSquared (LSQ) integration to capture comprehensive marketing attribution data by:
	•	Migrating from Create/Update API to Capture API endpoint
	•	Adding new custom attributes for improved lead source tracking
	•	Implementing intelligent source classification based on landing page slug patterns
	•	Maintaining backward compatibility with existing payload structure
2. Overview
2.1 Current State
We have successfully integrated the LSQ Create/Update API to pass Google and Meta leads with basic attribution parameters. The current implementation captures fundamental lead information but lacks detailed campaign tracking and source attribution capabilities.
2.2 Proposed Changes
This enhancement involves:
	•	API Endpoint Migration: Transition from Create/Update API to Capture API while preserving all existing payload attributes
	•	Enhanced Attribution: Add  new custom attributes to capture granular marketing campaign data including UTM parameters, ad identifiers, and user metadata
	•	Intelligent Source Classification: Implement automated source tagging based on landing page URL slug patterns
	•	Universal Latest Source Tracking: Extend latest_source attribute to all lead types including web_organic and app_organic.

5.3 Source Classification Logic (mx_Latest_Source)
Implementation Notes:
	•	Slug pattern matching should be case-insensitive
	•	Both google-lp and cfbc slugs map to google_lp source
	•	The mx_Latest_Source attribute will be captured for ALL lead types including organic traffic
6. Out of scope
	•	No change to existing lead capture flows in landing pages (all current forms, journeys, and triggers remain as-is in Curelo systems).
	•	No change to existing databases or internal storage of leads; Curelo will continue to store all lead data exactly as today.
	•	No UI/UX changes on website, landing pages, or app (no new fields, labels, layouts, or screens for this scope).
	•	No change to current validation rules or mandatory fields on UI; LSQ integration must work with the data already being collected.
	•	No changes to existing reporting/BI dashboards inside Curelo; any LSQ-based reports will be handled separately by the business/CRM team.
	•	No migration or backfill of historic leads into LSQ; scope is only for leads/events after this integration goes live.
7. Success Metrics
	•	100% of leads include new attribution parameters
	•	Zero data loss during API migration
	•	Successful phone-based deduplication rate maintained
	•	Accurate source classification for all traffic types
	•	Complete marketing attribution data available for analysis
